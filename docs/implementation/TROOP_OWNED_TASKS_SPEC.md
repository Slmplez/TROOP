# 子代理与所属后台作业

TROOP 0.4.0；[规格 #20](https://github.com/Slmplez/TROOP/issues/20)、[实现 #21](https://github.com/Slmplez/TROOP/issues/21)。承接已确定的 #4 执行契约，扩展 0.3.0 的本机 Agent；不是完整迁移交付。

## 使用与能力

用户从“任务”启动执行，由模型按需拆分。父任务的“子代理与后台作业”展示归属、状态和结果；“查看子代理”进入独立执行，写入与命令审批在该子代理的工具记录中处理。单项停止针对该作业及其后代；父任务停止针对整个所属树。独立创建的其他任务不受影响。

| 工具             | 参数                     | 行为                                                         |
| ---------------- | ------------------------ | ------------------------------------------------------------ |
| spawn_agent      | goal、access             | 创建 Task 与独立 child Run，access 为 read_only 或 inherit   |
| start_background | command、timeout_seconds | 对完整命令和时限逐次审批后创建后台 Task，返回稳定 task_id    |
| task_status      | task_id                  | 查询直接归属当前 Run 的作业状态及有界输出                    |
| wait_task        | task_id                  | 等待直接所属作业，不通过不断请求模型轮询；完成后接纳工具结果 |
| stop_task        | task_id                  | 持久记录停止意图，再停止直接所属作业及其后代                 |

task_id 和 timeout_seconds 使用十进制字符串。后台时限为 1–3600 秒，前台 run_command 继续保持 60 秒。stdout/stderr 各保留前 3000 字节，输出超过预算标注截断；运行中约每 500ms 提供一次累计输出，结束后提供最终结果。首版不提供 stdin、交互终端或 PTY，也不提供退出应用后持续运行的系统服务。

子代理使用同一工作区和冻结的模型配置/凭据引用，独立 Run ID、上下文、审批和工具账本；不会复制父对话全文。父模型明确写入子目标的内容会发送给子代理。read_only 只暴露目录、读取、搜索及任务管理能力；即使服务返回未声明的写入/命令，Core 仍拒绝执行。只读父代理不能通过 inherit 扩大子代理能力。inherit 不复用父工具审批，子写入、命令和 Git 查询仍单独批准。

并行仅指有界模型执行；本机工具仍采用宿主执行域排他队列。后台命令直到整棵 Windows Job 进程树停止并核对，才释放该资源。不同目录也不使任意宿主 Shell 获得隔离保证；外部编辑器不参加队列。本期不自动创建目录、worktree、转换平台命令或转移任务归属。

## 身份与事务

SQLite schema 4 新增 owned_tasks，Task ID 唯一关联创建它的 ToolInvocation。Task 保存 owner_run_id、parent_task_id、root_run_id、child_run_id、epoch、冻结参数、状态、停止/核对信息和 completion_id。只有 Core 写业务状态，Renderer 不能指定父子关系或替换参数。

创建 child Run、Task、父工具结果和父上下文在同一个事务提交，提交后才加入模型调度；后台 Task 与父工具结果也一起提交。所有权只沿创建链向下，首版没有转移/脱离入口，因此不会出现环或无主作业。进程 generation、Run epoch、Task ID、Invocation ID 与完成标识分别核对。

后台 Worker 复用受管 Job 和派发握手：Core 保存 dispatched → Worker 接受并写回执 → Core 保存 running → 发送 go → 执行。Worker 保存最终结果，Core 终止整个 Job 并检查 ActiveProcesses=0，再写停止确认回执并提交 Task 结果。派发前检查工作区仍指向冻结路径。Core 失去控制管道后 Worker 退出，Job 清理后代进程；不保证撤销外部服务效果。

## 完成与等待

Task 的最终状态、结果和稳定 completion_id 先持久化，consumed=false 充当完成 inbox/outbox。父任务在安全边界事务写入“接纳结果后的上下文 + consumed=true + 下一阶段”；事务失败保留原完成项。重复观察同一结果不会重复启动模型。

父模型流或前台工具仍在运行时，完成项只排队。待发工具结果先配对完整，再追加完成消息，不在协议的 tool_use/tool_result 之间插入用户消息。wait_task 的结果和消费标记同一事务提交。子输出作为不可信数据，不携带新授权；摘要最多 6000 UTF-8 字节，完整子输出仍在 child Run 中查看。

父模型提前给出最终文本时，只要还有所属活跃作业或未消费完成项，父 Run 就等待 background，不能显示 completed。作业结束后在安全边界交给模型汇总。中断或结果不明会暂停受影响的所属树，进入核对；失败的子作业也保留结果，父模型可以据此作出后续判断。

## 停止、失败与恢复

取消先持久保存所选子树的停止 fence，再撤销模型和受管执行。取消/失败意图不会被后续停止、补充输入或 resume 清除。父失败时同样清理其所属作业；仍在停止或状态不明时不伪装为完成。完成与取消竞争保留执行事实，不启动被停止树的后续动作。停止不回滚文件和外部副作用。

重启恢复业务记录，后台已派发但没有已接纳结果的作业标为 indeterminate，未派发和旧 child 作业标为 interrupted；不启动模型或重放命令。后台停止未确认时宿主执行域保持隔离。可接纳同时确认最终结果和整树停止的 Worker 回执；否则用户检查效果和进程停止，记录说明。子 Task 的核对要求先核对子调用及后代作业，不能绕过后代未知结果。

手动继续父任务之前必须核对其旧作业。旧后台命令和旧 child 不自动重建；父任务在新 epoch 根据已接纳结果重新规划。已核对、已消费或已停止归属中的 child 不能作为新独立任务重新运行。需要新尝试时创建新的显式计划和调用。预算包含原任务树历史，不因继续而重置。

显式退出关闭任务入口、停止活动树、保存 interrupted；托盘驻留继续运行。首版没有后台脱离或应用退出后自动工作。任务停止回执与“所有外部效果已撤销”是不同概念。

## 上限与接口

每棵树最多 8 个所属 Task，子代理深度最多 2；每 Run 最多 16 模型步骤、32 工具，每棵树累计最多 64 模型步骤、128 工具。最多 16 活动 Run，普通对话与 Agent 合计最多 4 模型流。上下文 192KB、模型文本 24KB、单次最多 8 工具的原限制继续适用。无自动重试或提供方切换。

内部协议升级为 4，新增固定方法 agent.tasks、agent.task、agent.stop-task、agent.reconcile-task；agent.get 附有界任务树摘要。已有 agent 接口保留。数据库从 v1/v2/v3 迁移到 v4；旧 Core 拒绝打开新库，运行中的用户旧实例不会由开发测试自动升级。

## 后续范围

记忆、压缩、Skills、Hooks、MCP、自动化、正式桌面接线、旧历史导入和签名安装包尚未包含。Docker 与 UI 美化继续延后；Windows 保持既定单屏基线。新增功能通过确定性服务与本机集成验收，不能替代所有真实提供方或一小时持续压力验收。
