# Agent 记忆与上下文压缩

TROOP 0.5.0；[规格 #22](https://github.com/Slmplez/TROOP/issues/22)、[实现 #23](https://github.com/Slmplez/TROOP/issues/23)。落实 #8 的记忆方向和 #4 的压缩快照要求。Agent 任务接入本功能；普通“对话”继续是直接模型入口，不自动变成 Agent 执行。

## 使用

“记忆”页选择 Agent，可保存、编辑、遗忘事实，管理项目成员关系与自动维护开关，查看维护提案、用量和失败原因。新 Agent 默认开启自动维护，高级合成默认关闭。任务启动时选择 Agent、模型与工作区；同一 Agent 的私有记忆跨工作区、跨任务复用。默认 Agent ID 为 1，旧 Run 升级后关联此配置。

用户自己编辑可见共享记忆时保留原分片来源，并标记为显式保存。修改使用记录版本检查；不会静默覆盖并发更新。遗忘使记录退出后续检索并留下删除保护，不承诺清除原任务历史、摘要、数据库残留或备份。

子代理继承所选 Agent 配置及可见记忆范围，仍拥有独立 Run、上下文和工具账本；同一 Agent 配置不是执行身份。只读子代理只可读取记忆，不能通过 update_state 修改事实或项目成员关系。子执行不单独触发自动提取，避免同一次所属任务被重复维护。

## 作用域与资料

| 作用域  | 可见性                   | 模型写入位置              |
| ------- | ------------------------ | ------------------------- |
| agent   | 仅当前 Agent             | 该 Agent 的私有记忆       |
| user    | 当前用户的 Agent 共享    | 当前 Agent 的用户共享分片 |
| project | 只有已加入该项目的 Agent | 当前 Agent 的项目共享分片 |

项目与工作区分开：选择一个目录不自动加入项目。update_state 的 target=project 支持创建、加入和离开；共享事实的写入、遗忘以及读取分别核验作用域。模型不能指定其他 Agent 身份，也不能借记忆操作扩大文件、命令或桌面授权。

profile 保留长期偏好与事实，log 保存带 UTC 日期、可按月份分组的记录，note 作为低权重 log；episode 是带前缀的阶段叙事。内容按旧机制折叠空白并限制为 500 字符，大小写归一键用于去重。显式事实、自动事实与删除保护分开记录。上限为 32 个 Agent、128 个项目、每 Agent 2000 条记录；UI 每页 20 条，不因共享资料增长而丢掉私有检索。旧目录和历史资料的导入仍由后续导入功能承接，本版不会自行扫描旧应用目录。

## 工具与注入

- update_state：target、action、content 必填；scope 默认 agent，tier 默认 profile，project 按作用域填写。记忆 write/forget 立即执行，不增加逐条确认；forget 要求事实的确切文本。
- recall_memory：可按 scope、project 和文字检索全部可见资料，返回最多 12 条并保留来源；不会读到其他 Agent 的私有分片。

注入上限沿用原机制：Agent profile/recent 为 100/30，用户共享为 50/15，每项目 25/10，最多 3 个项目；recent 每组最多 4000 字符，整体记忆注入另有 24KB 字节预算。log 按日期、episode 与 note 的权重排序。未注入的旧事实仍可检索。

快照按 compaction epoch 冻结，自动新增不会不停改写运行中的提示词。显式保存、编辑、遗忘和成员关系变更使后续模型请求刷新；已发送的请求与已进入历史的内容不能撤回。注入包含作用域、项目、Agent 来源、日期和 origin，明确记忆是数据而非授权。Anthropic 使用顶层 system，其他协议保留相应 system 消息。

## 自动维护

一次根 Run 正常完成后记录 user/assistant 交换，沿用寒暄过滤再提取；本机映射的结算单位是完整任务，而不是每个工具步骤。常规模式自动生成 additions/removals 提案，通过结构、预算、作用域和版本检查后写入；每六个合适任务另生成一次带日期的 episode。维护使用该任务冻结的模型服务及凭据引用，不另选商业专用模型。

高级合成开启后采用证据 → 提案 → 同一所选模型的独立验证请求 → 提交，不同时运行常规提取/episode；最多每 24 小时触发一轮。二次模型判断不等同外部事实核查。自动提案不能移除显式事实，不能引用未出现在快照中的删除目标，也不能恢复遗忘保护中的事实；可疑凭据格式及额外 JSON 字段会被拒绝。自动提取不改成“候选逐条批准”。

自动变化只写当前 Agent 私有分片。提交同时核对该 Agent 的私有资料版本与配置版本；不同 Agent 的独立维护不互相造成冲突。批次和维护终态一起提交；失败不留下半批事实，也不把已完成 Run 改成失败。

每个维护源有稳定 source key 和 Job ID，证据、提案、验证、尝试和请求次数持久保存。维护队列最多 64 项，同一 Agent 串行；与任务、压缩及普通对话共享全局 4 个模型流，前台任务优先。快照最多 500 个候选且不超过 48KB，证据最多 48KB，每批最多 12 个变化。没有自动重试；界面可停止维护，失败/中断后最多手动尝试三次。attempt 与验证阶段参与迟到结果检查，旧结果不能套用到新尝试。

显式退出停止维护并记录 interrupted；重启只恢复资料与记录，不自动请求维护模型。关闭维护开关会取消尚未完成的请求。模型失败可见，凭据引用和服务私有配置不通过公开 Job DTO 返回。

## 上下文压缩

工作上下文约到 96KB，或用户点击“在安全边界压缩上下文”时，在无待处理前台工具、无该 Run 模型流的安全边界启动。普通补充指令不强行中断当前工具。压缩也占据模型流额度，每 Run 最多四次，不重置原模型/工具/树预算。

原 history、ToolInvocation、冻结参数、审批和执行结果始终保留。压缩输入包含原目标、前一摘要、每条已提交记录的有界摘录/索引/指纹，以及完整的工具身份与状态摘要；单条摘录最多 512 UTF-8 字节，明确标注截断；不透明推理与签名块仅留原始协议档案，不进入摘要输入。摘要可能丢失细节，不能把摘录当作完整记录或新的授权。验收不承诺摘要的语义无损。

只有完整响应、最多 6000 字节的有效摘要可接纳。Core 核验 Run epoch、提交历史长度和 SHA-256 指纹，将覆盖游标、摘要、compaction epoch 与检查点在同一事务提交。模型视图使用摘要和覆盖游标之后的历史；不会把截断或删除后的数组冒充原始记录。

压缩期间到达的输入和所属作业结果先持久排队，在摘要之后的安全边界追加，不被旧摘要覆盖。停止后的迟到摘要不接纳；失败保留原历史并中断，用户核对后手动继续。重复压缩请求在等待/执行期间幂等，不重复启动模型；恢复也不重放已成功或结果不明的工具。

## 接口、升级与范围

内部协议 5；新增固定 memory.\* 管理、查询、维护控制接口及 agent.compact/checkpoints。SQLite schema 5 保留工作区、服务、会话、执行、所属作业和旧账本，增加记忆、版本钟、维护、证据与摘要表。旧 Core 不降级打开新库；开发验收使用备份副本，不自动升级或重启用户实例。

本功能不包含 Skills/Hooks/MCP、自动化、旧目录导入、正式桌面控制、安装包；Docker 和整体 UI 美化继续延后。真实提供方兼容、长时间负载和摘要质量需要独立证据，不能由本机协议夹具代替。
