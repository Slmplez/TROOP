# MCP 桌面管理与核对

2026-11-03，TROOP 0.10.1。实现 [#47](https://github.com/Slmplez/TROOP/issues/47)，父规格 #42，承接 #46。协议与 DB 继续为 10；新版本使用独立的 Core 文件，不替换正在运行的旧二进制。没有新增数据库迁移。

## 页面与操作

侧栏增加 MCP。左侧资料库显示服务名称、启停、传输、运行位置、来源与修订，右侧按配置、认证、任务连接分区。保存不会连接远端或执行命令，运行状态以具体任务的所属连接记录为准，不把“已启用”显示为“已连接”。已有任务的具体操作审批继续在任务页完成。

配置支持 HTTP、旧 HTTP+SSE、Windows stdio，保留旧 Linux 停用配置。可编辑 Agent 分配、原工具禁用名单、启动/调用时限、认证方式与凭据键。已有凭据值不回显，留空保留；删除字段名会移除对应保存值。启用 Windows 命令时，原生确认显示程序、参数和工作目录，并说明当前用户的宿主权限；取消不会保存。资料库命令不提供通用 Shell 执行。

配置导入先预览脱敏定义与秘密键名，再明确新建或更新目标及其修订；支持分页。预览不写库或凭据，导入保持停用且不分配 Agent。旧 Linux 不自动转成 Windows 命令。保存修订使用 Core 的比较检查，并保留来源、历史及冲突错误；前端不会自动重试写操作。删除要确认服务名，清理本机 OAuth 与配置凭据，保留执行记录；远端撤销未确认不能解释为远端权限已撤销。

任务目录来自 Run 的冻结快照，可读取后按原始名称开关，或直接编辑禁用名单。修改配置会使现有计划的旧修订失效，OAuth 也需要按配置修订重新连接。第一次任务发现前不伪造工具目录。

## OAuth 浏览器入口

保存服务后填写自有 Client ID、可选 Secret、Scopes，以及需要时的明确 issuer；动态注册由复选框明确选择。准备登录只启动 Core 的发现和 PKCE 流程，授权 URL 就绪后才显示“在浏览器中登录”。用户自行完成服务登录与同意；应用不提供嵌入式账号表单，不代点授权。

打开浏览器的 IPC 仅接受服务 ID 与认证修订，不接受 Renderer 提供的 URL。主进程重新读取 Core 的当前状态，必须仍为 authorizing 且修订匹配，才能打开当前 URL；地址仅允许 HTTPS 或明确 HTTP loopback，拒绝文件/脚本/data 协议、userinfo 和 fragment。没有向 Renderer 暴露通用 openExternal。

认证页显示取消、刷新、断开与远端撤销结果，以及配置过期、操作中断和凭据清理待完成等状态。断开立即停用本机凭据，远端撤销仍可能失败或结果不明。认证响应按修订接纳，旧轮询不能覆盖较新的授权状态；切换服务、重新连接 Core 和离开页面使旧读取失效。表单里的 Secret 不写浏览器存储。

## 调用与连接核对

任务页和 MCP 的任务连接区显示同一份 Core 账本：Run、服务身份/修订、传输、所属 Session、调用参数、结果与附件元数据。连接按页读取；调用结果与文字附件可查看有界页，跨 Run 和内容哈希检查由 Core 执行。二进制附件目前展示元数据，不执行、自动下载或内嵌预览。

HTTP 关闭表示本地通信结束，不能证明远端动作取消。结果不明时，用户填写调用核对说明并明确确认外部效果和操作停止。stdio 崩溃还可能留下独立的 Session 停止待核对，需另填说明确认整棵所属进程树停止。任务运行时不能核对连接；需要时先停止。没有 MCP Worker 文件回执时不显示原生工具的“核对 Worker 回执”按钮。

Core 的 agent.get 同时返回 mcp_unresolved，任务继续按钮在 Session 尚未核对时保持禁用。调用与 Session 核对不会自动续跑；用户回到任务页手动继续，旧调用不重放。连接区只在当前可见的任务页挂载，避免隐藏任务页留下重复控件；切换 Run/generation/调用后丢弃旧读取。

## 边界与验收方法

所有新增能力均为固定 IPC/预加载函数。原有 sender、主 frame 与页面 URL 校验同样应用于 MCP；Renderer 无 Node、Shell 或通用 invoke。Windows 本机能力继续按当前用户运行，不是 OS 沙箱。Docker、多屏与整体 UI 重设计保持暂停。

自动验收只使用自有 loopback 服务、临时数据库/文件和假凭据。桌面夹具经过真实窗口、预加载、主进程、Core、系统凭据及所属进程；原生确认和 OS 浏览器启动边界由自有夹具替代。PKCE 重定向、回调、token、刷新、撤销与已授权 MCP 调用使用真实协议实现。默认外部浏览器与真实第三方服务登录兼容仍需 #48 验收，不能由这些夹具代替。

最终回归：253 项 Node 集成测试通过（新增固定 IPC 边界 10 项），20 项 Rust 测试通过。Electron 管理页 10 组检查、基础 16 项、既有 Agent 6 项和 MCP 审批 3 项通过。Clippy all-targets -D warnings、Rustfmt、全范围 Prettier 通过。应用界面源码检查与真实浏览器快照复检均为 0 FAIL / 0 WARN；首轮发现的文字对比度及 660px 侧栏边距已修正。

界面验收覆盖服务保存/分配/启停、保存前无连接、目录与工具开关、三种模型协议与三种 MCP 传输、命令启用取消、取消后的旧授权链接拒绝、OAuth 业务调用/刷新/撤销、HTTP 不明结果手动核对与继续不重放，以及 Core 崩溃后的调用/Session 分开核对。固定 IPC 测试覆盖不安全 URL、修订过期与删除确认顺序。既有集成与 Electron 基础、审批流程作为回归。

设计沿用现有 Plex 与绿色灰框。应用规范采用 Framed sheet（seed 1781100963），保留配色和字体，无重抽；页面首先回答“哪个服务可供 Agent 使用，哪些任务还需核对”。服务修订与 Run 所属连接账本是核心信息，不添加 KPI 或装饰图表。按正式 Windows 最小窗口 660px 验证 1440/768/660px，无横向溢出；390px 手机布局不在本轮桌面范围。样例仅位于开发夹具，不进入产品初始数据。
