## 覆盖

本机集成覆盖真实 Core、SQLite、HTTP/SSE 三协议、Worker 文件操作和生产 Electron IPC。新增场景不调用用户保存的真实远程服务，不读取 API key，不操作用户项目目录。

- 三协议：显式 update_state 默认私有写入，重启后另一 Run 的请求实际注入；Anthropic system 位置正确。
- Agent 私有、用户分片共享、项目成员检查与离开后的可见性分开；编辑带版本检查。4200 条共享事实不会挤掉旧私有事实，分页及旧记录编辑正常。
- 自动提取直接写入、寒暄跳过；显式事实和遗忘保护保留；维护失败不改变 completed Run，只有人工点击才重试。
- 六个合适任务产生一个带日期的 episode；高级合成实际经过提案和第二次验证，验证拒绝/非法删除不应用。
- 四个独立 Agent 维护共享全局四流额度，新任务等待资源；独立 Agent 的写入可分别提交。
- 自动提案与并发显式编辑冲突时拒绝旧快照；关闭维护取消在途请求，Core 重启不自动续发。额外 JSON 字段不保留为公开提案。
- 不透明推理、签名和未知协议内容不进入摘要，原始协议档案仍保留。
- 三协议压缩大工具历史后继续，原始记录和 14 次工具调用保持；检查点、覆盖游标及 compaction epoch 实际落盘。
- 新输入和 child 完成到达压缩期间，不丢失、不重复消费；停止后的迟到摘要不创建检查点；文件写入不会因摘要再执行。

## 存储故障

只对隔离数据库注入 trigger：

1. 记忆工具结果事件提交失败：事实和调用结果一起回滚，没有幽灵记忆。
2. 自动批次第二项失败：第一项也回滚，维护失败可见，已完成任务不变。
3. 摘要检查点提交失败：原始 history 和已有文件保留；重启为 interrupted，不自动请求模型或重放工具。

这些是指定事务边界的证据，不是任意外部副作用 exactly-once 或断电保证。

## 桌面与升级

新增 Electron 检查通过生产界面保存/编辑事实、启动选定 Agent、核对真实模型请求注入、请求压缩/审批工具、查看摘要检查点、查看自动提取提案、遗忘和重载。1440/768/660 宽度检查无横向溢出，截图人工核对了文字换行和操作入口；沿用现有界面，不开展整体美化。截图内容为自有测试资料。

schema 4→5 分别验证用户已有备份副本与 0.4.0 任务账本副本：工作区、服务/凭据引用、会话、回合、工具、事件、所属 Task 哈希保持；Run 除新增默认 agent_id 外原内容保持。原始数据库未写入。v1→当前迁移及更高版本数据库拒绝由既有 Rust 测试覆盖。

本机日志、隔离配置、回执、迁移副本和截图在被忽略的 .tmp-troop-memory/；final-tests.log、latest-memory-smoke.json、latest-migration.json 指向本轮证据。临时数据不随源码发布。

## 限制

这证明本次确定性服务和 Windows 集成行为；新增维护/压缩场景没有真实远程提供方验收。未做长期负载、所有自然语言的事实准确性评测、旧记忆目录导入或签名安装包。模型审查不是事实真实性证明；压缩使用有界摘录，原始工具账本始终可查。普通对话仍是直接模型入口；Agent 配置的长期记忆用于任务执行。

Docker/UI 美化与后续集成保持原范围，#9/#10 完整产品门槛不关闭。
