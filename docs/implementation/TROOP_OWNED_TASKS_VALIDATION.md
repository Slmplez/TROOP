## 核心场景

- 三协议实际创建独立 child Run：子上下文不包含父目标原文，读取真实临时文件；完成项只消费一次，重启不请求模型。
- 只读子代理不暴露命令工具；服务即使返回未声明的 write_file，也不会产生写入或审批等待。深度 2 时拒绝继续创建后代。
- 后台命令批准前没有 Task 或文件效果；批准后产生真实文件、累计输出与最终结果。后台期间其他宿主工具保持 prepared/resource，进程树结束后才执行。
- wait_task 等待期间模型请求数量不增长；结果与已消费标记一同提交。父模型先给出最终文本时仍等待所属作业，全部处理后才完成。
- 父等待后台期间收到补充指令，在安全边界调用 stop_task，命令不必运行到时限才处理输入。
- 父停止传播至 child 与后台命令，真实心跳文件不再增长。停止后的树不因旧回复或 resume 恢复；产物保留。
- 模型失败时清理仍所属的后台命令，失败意图保持。不同 Run 的 task_status 无法读取其他 Run 的作业。
- 实际终止 Core 后，后台心跳停止。重启不发送模型请求；未核对的 Task 阻止继续，人工核对后手动继续不会重跑原命令。
- 后台超时导致 child 与父中断；核对 child Task 前必须先核对其后代。继续父任务不会重启旧 child。
- 显式退出停止嵌套作业；重启父子均为 interrupted，没有自动请求或遗留心跳。

## 提交故障与回执

在隔离数据库中注入 SQLite trigger：

1. owned_tasks 插入失败：child Run 创建与父工具修改回滚，没有子模型请求或孤立 child。
2. 最终业务结果提交失败：Worker 的完整结果和 Job 停止确认回执保留。重启核对原回执后手动继续，原命令仅在文件中写一次。
3. 完成项消费提交失败：Task 的成功结果和 consumed=false 保留。重启不自动推进；手动继续后完成标识只进入下一模型上下文一次。

这些验证证明指定提交边界的事务与去重行为，不承诺任意外部服务 exactly-once、断电恢复或外部副作用可撤销。

## 界面与本机资料

新增 Electron 验收实际点击生产入口的启动、查看子代理、审批后台命令、查看累计输出、停止所属作业、填写核对结论和结束父任务；使用真实 preload/固定 IPC/Core，不替换执行接口。1440、768、660 宽度没有横向溢出，截图检查了归属、状态、文字换行和操作入口。

界面沿用现有 Framed sheet 外壳、品牌和字体，只加入功能入口。设计参考 seed 1239239237；新增组件源码 lint 0 FAIL/0 WARN。用户明确延后 UI 美化，本轮不做整体视觉重构或手机规格扩展。截图中的英文标题和命令来自自有测试夹具，正式界面读取实际 Task 数据。

本机证据在忽略目录 `.tmp-troop-tasks/`：final-tests.log、latest-tasks-smoke.json、latest-migration.json；原有 Electron 证据仍在 `.tmp-troop-bootstrap/` 和 `.tmp-troop-agent/`。临时数据库、用户备份、命令回执和原始配置不发布。

## 限制

本阶段没有新增真实提供方调用；原 0.3.0 的指定 Anthropic 服务证据只作为既有基础能力，不冒充新子代理场景已通过远程服务验收。未实跑一小时持续作业、长期压力、交互终端或干净机器安装包。本机 Shell 按当前用户权限运行，不是 OS 沙箱。旧用户实例不因开发测试自动重启或升级；手动启用新版前应先从托盘退出旧实例并备份数据。

Docker、UI 美化、记忆/压缩、Skills/Hooks/MCP、自动化与正式桌面接线仍在后续范围，#9/#10 完整版本门槛没有关闭。
