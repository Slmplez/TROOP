# F2 预约复查与 F3 原生协作链验证

2026-11-08，Windows，隔离 Core 资料目录、本机模拟模型和真实 Electron。当前记录覆盖原生跟进与交接增量。完整 J1、四 CLI 的跟进专项和真实 GitLab 平台验收继续单独收口。

## 实现范围

- schema 30 保存跟进策略状态、协作链和预约身份。旧 schema 29 迁移保留工作项及规则。策略、预约、工具结果、工作关联、链计数和操作回执使用既有账本事务，提交后激活运行时。
- `followups.preview/list/get/history/save/request/run/set_enabled/cancel` 提供预览、策略编辑、有限期预约、手动检查和历史。相同预约请求返回原记录，身份冲突拒绝。错过五秒容差的自动预约保留阻断记录，补跑使用明确新身份。
- 原生受控工具 `propose_followup` 绑定当前工作和来源 Run，要求检查时间、理由和预期变化。每次到期创建独立检查 Run，有界输入保存工作定义、来源输出片段及修订、预约、当前期限、剩余启动次数和已确认交接路由。
- 同一工作串行推进。当前执行、CLI 审核、未核对效果和依赖门禁继续生效。跟进允许对已结束但尚未验收的原生检查再次观察，工作历史保留各版本，工作完成及依赖释放仍由明确验收决定。
- 原生 `request_handoff` 和 `followups.handoff` 仅使用预配置的接收策略。双方属于同一项目与工作区，接收方当前授权与来源能力上限完全一致，派发前再次检查路由、依赖、授权、工作定义和代次。
- `followups.chain/stop_chain` 查询及停止同一因果链。停止先增加代次并取消待处理预约，再停止关联 Run 与所属 Task。停止事务提交失败时，代次、执行和预约一并回滚。重复操作沿原回执查询。
- 暂停或取消策略使旧预约失效，在途执行保留原事实。恢复处理新预约。停止来源 Run 后，旧来源预约无法启动新 Run。根工作取消、期限到期和上游群协作失效会停止因果链。
- 群来源的跟进共用上游启动计数、并发、期限和累计模型／工具用量。停止群协作链会同时封锁并停止它产生的跟进执行。
- 规则页新增持续跟进配置、交接目标、预约、历史、工作结果入口及停止范围。草稿按窗口和资料库隔离，重载保留，旧修订禁止覆盖其他窗口修改。整链停止先读取当前链修订。

## 工程保护值

表单初值为最多四次启动、最小一分钟间隔和三十分钟期限，时间输入使用 Asia/Shanghai。

Core 接受一至十六次启动、最小间隔一分钟至一天、最长三十天且不超过授权到期时间。每策略最多八个待处理预约、八个预配置交接目标。链内同时最多两个 Run，原生累计最多六十四个模型步骤和一百二十八个工具调用。修改策略保留已消费计数，交接继承原链计数。

## 验证结果

跟进专项包含十九个公开 API 回归，覆盖持久身份、重启、旧库迁移、撤权、错过预约、暂停恢复、双 Agent 往返交接达到上限、未验收依赖、来源停止、停止回执故障回滚、群来源限额和群停止传播。结果包含在 [全量桌面日志](full-desktop.txt)，专项迭代记录见 [Core 日志](core.txt)。

最终桌面全量回归共六百五十项，六百二十七项通过、二十三项按各自环境条件跳过，失败为零。验收发现并修复了忙碌工作项交回时的预约排队竞态。原生工具使用真实授权时钟，受控调度测试按交接实际时间推进，避免固定测试时钟跨秒后预约一直未到期。

真实 Electron 验证通过，使用生产 Renderer 构建。覆盖权限预览后修改使确认失效、重复点击仅保存一个策略、手动检查、重载草稿、多窗口修订保护、暂停恢复、整链停止及重启后保持停止。三个桌面宽度无横向溢出。见 [桌面报告](followups-smoke.json)和 [Electron 日志](electron.txt)。

已检查 [1440 截图](followups-1440.png)、[768 截图](followups-768.png)、[660 截图](followups-660.png)及 [整链停止截图](followups-stopped.png)。沿用现有工作台配色和字体，采用 framed-sheet 表单布局，预约原因、时间及执行事实随记录展示。界面针对最低 660 像素桌面窗口验收。

design-taste-frontend 源码检查无失败及告警。实际 Electron 页面使用技能的 probe 和 judgeApp 检查，三个宽度均无发现。桌面保留未激活面板，标题检查改为选择首个可见 h1，调整记录在各检查文件中。见 [源码检查](design/lint.txt)及 [1440 检查](design/inspect-1440.json)、[768 检查](design/inspect-768.json)、[660 检查](design/inspect-660.json)。

Rust workspace 五十七项测试通过，严格 Clippy、生成契约一致性、客户端 TypeScript 类型检查和产品计划检查通过。Rust 凭据用例需要 Windows 凭据访问，受限沙箱返回系统错误码 5 后，在允许的宿主测试环境复跑通过。桌面协议测试占用 probe.exe 时曾阻止链接器更新，桌面测试结束后串行复跑通过。见 [Rust 日志](rust-test.txt)、[Clippy 日志](clippy.txt)和 [构建日志](build.txt)。
